CORE PRODUCT VISION
============================================================

Build a complete ecommerce ecosystem capable of receiving
authorized product information from supported WhatsApp
Business/Meta sources and transforming that information into
structured ecommerce products.

The system should be able to process authorized incoming
content containing:

- Product images
- Product videos
- Product title
- Product description
- Product specifications
- Product quality
- Product condition
- Product pricing
- Discount pricing
- Product category
- Brand
- Model
- SKU
- Availability
- Stock information
- Warranty information
- Seller-provided information
- Additional product notes

The system must intelligently extract, normalize, classify,
validate and organize the information.

The final result should be a beautiful ecommerce catalog where
products are automatically placed into the correct category.

============================================================
CRITICAL WHATSAPP COMPLIANCE REQUIREMENT
============================================================

The system MUST use only authorized and supported WhatsApp/
Meta APIs, WhatsApp Business Platform functionality,
webhooks, catalog/business integrations, or other officially
permitted data sources.

DO NOT:

- Scrape private WhatsApp groups.
- Bypass WhatsApp authentication.
- Extract content from private conversations without
  authorization.
- Use unauthorized WhatsApp Web automation.
- Steal media from private channels.
- Circumvent WhatsApp rate limits.
- Circumvent Meta API restrictions.
- Store personal WhatsApp information unnecessarily.

The architecture must support legitimate sources such as:

- WhatsApp Business Platform
- Authorized business conversations
- Authorized business media
- Authorized catalog/business data
- Officially supported webhook events
- Other authorized Meta integrations

If a requested WhatsApp source cannot legally or technically
be accessed through an official API, DO NOT invent an API.

Instead:

1. Clearly identify the limitation.
2. Implement an adapter/interface for future supported access.
3. Provide an alternative authorized ingestion mechanism.
4. Continue development using mock/test data.

============================================================
IMPORTANT DEVELOPMENT RULE
============================================================

DO NOT attempt to build the entire application in one step.

Build the application in clearly separated phases.

After each phase:

1. Compile/build the project.
2. Run automated tests.
3. Run static analysis.
4. Check database integrity.
5. Check API contracts.
6. Check UI navigation.
7. Check authentication.
8. Check error handling.
9. Check responsive behavior.
10. Fix discovered problems.
11. Re-run tests.
12. Only proceed to the next phase after the phase
    acceptance criteria are satisfied.

Never hide errors.

Never silently ignore failed tests.

Never fabricate unavailable API capabilities.

Never replace production functionality with fake
implementations without clearly marking them as mock/stub
implementations.
